# 巡检工具 V5（个人版）· 含「环路告警」页签

在 V3 的全部功能（单机 / 批量巡检、配置备份、流量测试、安全核查、主动探测）之上，
**新增第 8 个页签 `Ring Alert`**：检测环路特征与硬件劣化，每条告警都带**原始证据行**。

> 环路问题的关键：**要看"变化量"，不能只看一次快照**。所以页签里主力用法是
> **两轮采样**（工具自己连设备跑两遍，间隔可设）。也可以在页签里直接分析历史报告。

---

## 一、页签怎么用

### A. 在线两轮采样（主力）

1. 设备文件：填 txt / xlsx（留空则自动用「批量巡检」页当前选的设备文件）；
2. 两轮间隔：默认 **30 分钟**（建议 15~60 分钟）；并发设备数默认 8；
3. 采样命令：已预置华为的 10 条（`display stp` / `mac-address` / `interface` /
   `interface brief` / `device` / `logbuffer` / `alarm active` /
   `transceiver diagnosis interface` / `temperature all` 等），可自行增删；
4. 勾好检测项 → 点「开始两轮采样分析」→ 跑完两轮自动出告警表。

> 巡检是**只读查询**，但仍会登录设备，请确认已获授权（弹窗也会再确认一次）。
> 间隔期间可随时「停止」。

### B. 离线分析报告

选 1 份或 2 份巡检导出的报告 CSV → 点「分析这两份报告」。
适合事后复盘，或"只有报告、没有设备访问权限"的场景。

| 想看什么 | 报告份数 |
|---|---|
| 日志告警事件、光功率越界、温度/组件异常（关键字类 + 绝对值类） | 1 份 |
| **MAC 漂移、CRC 增长、广播速率、链路震荡、TC 增量** | **2 份（差分）** |

### 结果区

* 表格按级别着色（**红=高危 / 橙=一般 / 黄=提示**），双击看**完整证据 + 建议动作**；
* 「⚠ 上一异常 / ⚠ 下一异常」可直接跳，不用从头翻；
* 支持按级别筛选 + 关键字搜索；
* 「导出 HTML / CSV」**弹对话框自选保存路径**（记住上次目录）。

## 二、检测项

| 编号 | 名称 | 判据要点 | 数据来源 |
|---|---|---|---|
| D1 | MAC 漂移 | 同一 MAC+VLAN 两轮间换了端口 | `display mac-address` |
| D2 | STP 拓扑变化 | 每分钟 TC 增量超阈值（按设备档：接入 5 / 汇聚 15 / 核心 30） | `display stp` |
| D3 | 根桥变更 | 根桥 ID / 根端口变化 | `display stp` |
| D4 | 广播/组播风暴 | 广播+组播包速率超阈值 | `display interface` |
| D5 | 接口误码增长 | CRC / 输入错误每分钟增量超阈值 | `display interface [brief]` |
| D6 | 链路震荡 | 每小时 up/down 次数超阈值 | `display interface` |
| D7 | 厂家日志关键字 | 日志事件名映射（**完整事件名，非裸词**） | `display logbuffer` / `display alarm active` |
| D10 | 光衰 | 收光功率过低 / 两轮下降 > 3 dB / 模块自报越界 | `display interface`（Rx/Tx Power 行） |
| D11 | 温度 | 超阈值或快速升温 | `display temperature`（部分机型不支持） |
| D12 | 电源/组件状态 | 任一组件状态非 Normal；正常数减少（冗余丢失） | `display device` |

### 完整版独有（深度项，默认不勾）

| 编号 | 名称 | 说明 |
|---|---|---|
| D8 | BPDU 收发异常 | BPDU 速率异常；收到本机 Bridge ID 的 BPDU = **自环特征** |
| D9 | 跨设备关联 | **同一 MAC 同时出现在两台设备**（环路强证据）；多台设备同一采样窗口 TC 同时跳增 |

## 三、改规则：只改 `rules.yaml`

程序同目录的 `rules.yaml`（首次运行自动释放）是唯一的规则数据文件：**阈值 + 关键字**。
改完点页签里的「重新加载规则」生效，**不用重新打包**。

### 加关键字（重点）

关键字是**正则**，大小写不敏感，`.*` 是"全厂商通用"键，其他键写厂商名（huawei/h3c/...）。

⚠️ **绝对不要用裸词**：`Alarm` 会命中日志里 `alarmID=0x…` 这类正常字段（实测误报 256 次）。
要写**完整事件名**：

```yaml
signals:
  MAC_FLAPPING:
    severity: high
    patterns:
      huawei: ['MAC/4/MAC_MOVE', 'MAC.{0,20}(MOVE|FLAPPING|FLAP)']
      '.*':   ['MAC_FLAP', 'MAC_MOVE']
```

**怎么找出自己设备的事件名**：把日志输出抓出来，用这条正则统计：

```
%%\d+([A-Za-z0-9_]+)/(\d)/([A-Za-z0-9_()\-]+)
```

> ⚠️ 量大但正常的事件**不要收**（例如 BRAS 用户侧上下线，一天几百条）。
> 判断标准：这条事件**每个健康设备上都有** = 噪声。

## 五、已知限制（务必知道，避免误判）

1. **单轮看不出"正在增长"**：CRC 等计数器是**历史累计值**（可能是几年前留下的）。
   → 判断"还在恶化"必须两轮差分。
2. **命令可能不被设备支持**：例如 ME60 上 `display transceiver` / `display temperature`
   会报 `Unrecognized command`。程序会记进「检测能力提示」，**不会误报告警**。
3. **日志关键字会命中例行事件**：链路 up/down、MSTP 端口转发在正常变更时也打日志。
   → 必须看证据行判断，别只看红点。
4. **光功率判据**优先采用设备自报的告警门限（`Warning range`）；模块型号未知时只信趋势。
5. **每台设备同类信号最多报一次**（去重，避免刷屏）。
6. **解析器目前只完整实现华为**；其他厂商的命令能跑，但结果会记入"检测能力提示"，
   拿到真实输出后按下面方法补。

## 六、扩展新厂商（例：华三）

1. 在 `ring_parsers.py` 里仿照 `parse_huawei_*` 写 `parse_h3c_*`
   （**必须先拿到真实命令输出再写正则**）；
2. 加 `_H3C_PARSERS` 命令映射，并在 `parse_device_sample` 里按 `vendor` 分流
   （现在非 huawei 会返回"解析器尚未实现"并记入 unsupported，便于发现遗漏）；
3. 在 `rules.yaml` 的 `signals.*.patterns` 里补 `h3c:` 关键字（用真实事件名）；
4. 用真机输出验证：打印 `parse_device_sample()` 结果 + 跑 `test_ring_rules.py`。

> 铁律：**解析器要对着真实输出写**。凭印象写正则一定会在某天静默漏采或误报。

## 🚨 故障视图（v5.2.0 新增 · 面向"不会数通的人"）

Ring Alert 页签的结果**默认显示「故障视图」**：不再是上百条散点告警，而是**几个故障**，
每个故障都直接回答操作员最关心的四件事：

```
❗ 故障 1｜二层环路（网络里有一根线接成了圈）   ← 先处理这个
──────────────────────────────────────────────
故障设备：10.21.11.193      置信度：高
涉及告警：4 条（D13×1、D4×1、D7×2）

【现象】
  · 涉及端口 10 个：XGE0/0/2、XGE0/0/3 …
  · 广播量最高约 7244 pps（正常应低于 1000）
  · 源头 MAC：f033-e508-0567   涉及 VLAN：1000
【判断】
  同一个 MAC 同时出现在这些端口上 → 这些端口之间被线路环接了。
【怎么处理】
  先拔掉 **XGE0/0/3** 的网线，等 1 分钟看广播量有没有降下来
  若没降，继续依次拔 XGE0/0/4、0/0/5 …
  降下来的那一根就是环路的接入点；顺着它找另一端（多半私接了台小交换机）
```

- **聚合**：同一设备的「多端口同速率广播 + 环路日志 + 同 MAC 多端口」→ 合成**一个**故障
- **根因打分**：同设备同 MAC 多端口(★★★) · 跨设备同 MAC(★★★) · 设备自检环路日志(★★★) ·
  多口同速率(★★) · MAC 漂移(★) → 排出"最可能的故障点"，第一条标「先处理这个」
- **单端口轻微广播**不会升级成故障，统一并入一条「终端广播异常（大概率不是环路）」
- 需要技术细节时，右上角切到「**告警明细**」看逐条证据（原表格视图不变）
- 导出的 HTML 报告同样**故障清单置顶 + 明细在下**

**新判据 D13｜同设备 MAC 多端口冲突**：同一 MAC（同 VLAN）出现在同一设备的 ≥2 个非聚合端口
→ 单轮即可判定，直接给出"哪两个口之间被环接了"（D4 也从"逐口各报"改为"环路组聚合"）。

**采样体检**：每次采样会逐条记录命令的字节数/行数/是否报错，用来区分
「命令没拿到数据（设备不支持/大表被截断）」与「拿到了但没发现环路」；页签提供**大表模式**（更大的静默窗口与超时）。
